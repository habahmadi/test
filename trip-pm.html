Trip postMessage origin-check test (step 1)

Authorized bug-bounty test — HackerOne handle sshabib. Benign marker only, no real OAuth code.

  1. Click Open Trip login — a popup opens to www.trip.com/account/signin.
  2. In that popup, open DevTools → Network, tick Preserve log, filter for authenticateTrip.
  3. Click a social login button in the popup (Google) so the SDK arms its message listener. A provider popup may open — you can ignore/close it.
  4. Come back here and click Fire forged message (or it auto-fires 20s after you open the login).
  5. Watch the popup's Network tab (see below).



What proves the vuln


In the Trip popup's Network tab, look for an outbound POST to:


gateway/api/soa2/14553/authenticateTrip


Open it → Payload/Request → find Data.authCode.


    
  
  • authCode == "STEP1_MARKER_NOT_A_REAL_CODE" → PASS: the handler ingested our cross-origin message with no origin check. (Server will reject the fake code — expected.)
    • 
  
  • No such request / marker absent → the listener wasn't armed or the handle path differs; tell Claude and we adjust the trigger.
